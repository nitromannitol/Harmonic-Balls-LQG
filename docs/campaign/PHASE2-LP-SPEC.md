## 0. Method and counts

- **Closure.** For each input, start at its head constant and follow `Expr.getUsedConstants` over its type and value (constructor types for structures, statement only for theorems). A constant is expanded only if its module starts with `HarmonicBalls`; all others are leaves. The 45 closures reach only `Init` and `Mathlib`: no MarkovProcess or elliptic_regularity constant occurs.
- **Not listed:** constructors, `.mk`, `.casesOn`, `.match_n`, `.rec` (their fields are reached through the structure). `GFFObservable` and its six functions are folded into one entry, shown as `GFFObs(7)`.
- **Counts:** 45 rows, 31 distinct closures; 79 non-input HB definitions (73 entries after folding); 28 helper theorems (`_proof_k`) inside bodies, counted per row, not listed.
- **GEN** = closure has no HB definition and no helper. **M0** = GEN; **M1-M6** = the LP modules of section 3. `uses` = counted declarations using the input (inventory column).
- **Paths** are `HarmonicBalls/<path>`; line numbers are the line of the `def`/`structure` keyword in the current source (the built declaration ranges start at the docstring and can differ from the source). `[deps]` = direct HB dependencies, auxiliary constants expanded.
- **Verdicts** against the catalog: `none` = no counterpart; `part` = role or name matches, carrier or signature differs; `diff` = same name or role, different notion. The legend gives the reason. LP paths are relative to the LatticeProb repository (`Bonanno/...`, `Analysis/...`). Only the catalog lines and HB headers named there were read.
